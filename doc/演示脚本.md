# C2C Protocol · Builder Hub 评审 Demo 脚本（3 分钟）

> 配套：Dashboard（`apps/web` :3001）· NestJS api（:3000）· Hardhat(31337) · Docker PG · Kubo IPFS(可选)
> 设计基准：`doc/实施方案.md §11 Demo 故事线`。
> 页面已内置两种演示能力：
> ① **Run Reputation Simulation**（前端概念模拟条：任务完成 → AI 验证 → +Reputation → Proof → Avalanche）
> ② **LIVE 轮询**（右下角按钮，每 5s 拉真实 `GET /agents`；现场跑 seed 时右上角弹真实活动 toast）

---

## 0. 开场 15 秒（只开 Dashboard 页）

**一句话定位**：AI Agent 能干活，但互联网上没有"信用记录系统"。你愿意把生产代码交给一个 0 历史记录的 Agent 吗？C2C 就是给 Agent 建信用账本——每一次真实协作产生可验证的链上声誉。

**指向页面**（不用念太多）：
- 左侧 **Agent Ranking**：真实注册的 6 个 Agent，按声誉排序
- 右侧详情：**Composite Score 环形分 + 四维雷达图**（Execution 30 / Reliability 30 / Quality 25 / Collaboration 15）
- 强调一句：**"这些不是 mock 数据——每个分数背后都是链上 Proof Hash + 真实交易。"**

---

## 1. 现场跑真实链路（第 2 幕，最有说服力的 45 秒）

**前置**（评审前 10 分钟在后台起好，勿当场起服务）：
```bash
pnpm db:up && pnpm db:migrate      # Docker PG + 表结构
pnpm chain:node                    # hardhat node :8545（持久）
# 另开终端：
pnpm deploy:local                  # 部署 5 合约（含 TaskRegistry）→ contracts/deployments/hardhat.json
pnpm api:start                     # NestJS :3000
pnpm web:dev                       # Next :3001
```

**当场操作**：
1. Dashboard 右下角确认 **LIVE 亮绿**（每 5s 刷新）
2. 切到终端，跑：
   ```bash
   pnpm seed:e2e
   ```
   终端会滚动打印：注册 Agent → 发 task 事件 → EIP-712 签名 → **txHash / IPFS CID / Proof Hash**
3. **切回 Dashboard**（不用刷新！）：右上角弹出真实 toast「新 Agent 注册 / 评分更新 / 链上验证」，左侧列表出现新 Agent，分数/雷达实时变化。

**台词**："注意看，我没刷新页面——右上角这些通知是刚才终端里那笔真实交易的结果。每一个都是 Fuji 链上可查的。"

---

## 2. 链上验证（第 3 幕，30 秒）

点开最新 Agent：
1. **Composite Score 大数字** → 对应雷达图四维
2. **Proof Hash**（如 `0xd2f44f29…`）→ 指向 IPFS 内容寻址的原始证明 JSON
3. 说明可验证性："评分的原始输入、权重、proof 全部公开可重算；哈希已锚定上链，改任何一位数都会对不上。"

> 若在 Fuji 真网演示：打开 Snowtrace 搜 txHash / Passport NFT，展示 `ScoreUpdated` 事件。
> 本地 Hardhat 无浏览器 explorer，用终端 `pnpm --dir contracts exec hardhat console` 查询兜底。

## 3.5 任务市场（人发布任务 → Agent 领取，可选加场 45 秒）

页面底部 **Task Marketplace** 面板演示「人机协作的声誉门槛」真实链路：

1. **发布任务**：填标题/描述 + 设声誉门槛（如 `6000`）→ 点「发布并上链登记」
   → 后端算 taskHash → 调 `TaskRegistry.publishTask` 链上登记 → 列表出现 `OPEN` + 「✓ 链上已登记」
2. **低分被拒**：切「领取身份」为未评分 Agent Owner（如 #3，score 0）→ 点「领取」
   → 弹 `403 TASK_REPUTATION_TOO_LOW score=0 required=6000`
3. **高分领取**：切到已评分 Agent（如 #2，score 6402）→ 领取成功 → `ASSIGNED` + assignTx 上链
4. （终端可选）SDK 完成任务：`taskId=externalId` 发 `task.completed` → 事件对账 `COMPLETED`，
   该 Agent 声誉再上链（如 6402 → 7414）

**台词**："这就是声誉作为生产力门槛——分不够的 Agent 连活都接不到。
这不是 mock：任务发布/领取/完成都在 TaskRegistry 合约上留了可查记录。"
**诚实边界**：V1 无支付/撮合；页面标注 Demo，领取用演示私钥直连（生产走钱包签名）。
